# Bead Belt

Одно­касательная головоломка: нажимаешь на лотки сверху, шарики едут по конвейеру и падают в коробки своего цвета. Конвейер ограничен: забит и нет подходящих коробок — проигрыш.

Capacitor (Android) · чистый JS + Canvas, без сборщика · сборка в GitHub Actions · публикация в Google Play.

## Быстрый старт

```bash
npm install
npm run dev          # игра в браузере: http://localhost:5173 (удобно с эмуляцией телефона в DevTools)
npm test             # проверка уровней + симуляция ботами
```

Откройте папку в VS Code: во вкладке Terminal → Run Task есть готовые задачи.

### Android

```bash
npm run android:init     # cap add android + иконки + патч под Google Play + cap sync
npm run android:open     # Android Studio (нужны JDK 21 и Android SDK 36)
```

После правок в `www/` достаточно `npm run android:sync`.

## Устройство игры

Слои: правила игры (без DOM) → модель отображения (без DOM) → отрисовка → интерфейс. Каждый модуль отвечает за одно.

| Файл | Что делает |
|---|---|
| `www/js/levels.js` | данные уровней (лотки, очередь коробок, вместимость конвейера) |
| `www/js/game.js` | правила: лотки → накопитель → конвейер → коробки, победа/поражение |
| `www/js/bin.js` | накопитель: физика кругов с фиксированным шагом 1/120 с |
| `www/js/particles.js` | искры и конфетти (не влияют на правила) |
| `www/js/geometry.js` | координаты поля и траектория конвейера |
| `www/js/solver.js` | дискретная модель уровня, проверка проходимости |
| `www/js/viewmodel.js` | модель отображения: позы лотков/коробок/шариков, раскладки, «туман» (тестируется в Node) |
| `www/js/anim.js` | easing и clamp |
| `www/js/render/index.js` | порядок слоёв кадра, тема, масштаб |
| `www/js/render/cache.js` | кэши готовых картинок и offscreen-слои |
| `www/js/render/theme.js` | палитра шариков и темы холста |
| `www/js/render/marble.js`, `shadow.js`, `draw-util.js` | спрайт шарика, тень, примитивы |
| `www/js/render/trays.js`, `bin.js`, `belt.js`, `boxes.js`, `panel.js`, `effects.js`, `hint.js` | отрисовка частей поля |
| `www/js/main.js` | связывает экраны, ввод, настройки и цикл |
| `www/js/navigator.js`, `frame-pacer.js`, `quality.js`, `viewport.js` | навигация по экранам, политика кадров, адаптивное разрешение, размер холста |
| `www/js/i18n.js`, `www/js/ui/*` | строки ru/en и отображение интерфейса |
| `www/js/audio.js`, `platform.js`, `storage.js` | звуки (WebAudio), вибрация/«Назад», сохранение |

Физика есть только в накопителе (до 30 шариков, дёшево). Шарики на конвейере едут по заданной траектории, поэтому поведение стабильно на любом телефоне.

## Как добавить уровень

1. Добавьте объект в `LEVELS` (`www/js/levels.js`). Для каждого цвета число шариков в лотках должно равняться `3 × число коробок`.
2. `npm run validate` покажет, проходим ли уровень, **минимальную вместимость конвейера** и долю «безопасных» первых ходов. Хороший уровень: проходим, запас небольшой, не все первые ходы выигрывают.
3. `npm run simulate` прогоняет реальную симуляцию: бот по решению обязан выиграть, случайные боты не должны зависать.
4. `npm run test:view` проверяет модель отображения, политику кадров и адаптивное качество.

CI запускает обе проверки на каждый push, так что непроходимый уровень не доедет до игроков.

## Сборка (режим разработки, без публикации)

`.github/workflows/android.yml` на каждый push / PR / ручной запуск:

1. `npm test`: уровни, симуляция, согласованность версии;
2. собирает `bead-belt-<версия>-debug.apk` и `-release.apk` и кладёт их в **Artifacts** запуска. Больше ничего никуда не уходит.

Локально: `npm run android:apk` (нужны JDK 21 и Android SDK 36), файлы в `android/app/build/outputs/apk/`.

### Подпись

Все сборки подписаны **одним публичным ключом** `signing/dev.keystore` (пароль `beadbelt`, см. `signing/README.md`). Новый APK ставится поверх старого без удаления игры.

### Версии

Формат `X.Y.Z`, каждая цифра 0–9, счёт идёт в последнем разряде с переносом: `0.0.1 … 0.0.9 → 0.1.0 … 0.9.9 → 1.0.0`. `versionCode = X*100 + Y*10 + Z`, поэтому он всегда растёт. Версия видна в меню игры.

```bash
npm run bump      # +1 к версии (package.json и www/js/version.js)
```

Поднимайте версию перед каждой сборкой, которую будете ставить на телефон, иначе Android не примет её как обновление (тот же `versionCode`).

Публикация в Google Play отложена: см. `docs/PLAY_LATER.md`, тексты и политика в `docs/`, графика и скриншоты в `store/`.

## Важно знать

- Android-проект (`android/`) генерируется командой `cap add android` и не лежит в репозитории: при первой сборке версии Capacitor/Gradle берутся актуальные (`"latest"` в `package.json`). После первого `npm install` закоммитьте `package-lock.json`, чтобы сборки были воспроизводимыми.
- `scripts/patch-android.mjs` рассчитан на Groovy-шаблон Capacitor (`build.gradle`). Если шаблон изменится, скрипт остановится с понятной ошибкой, а не испортит проект.
- Графику и иконки можно пересоздать: `python3 tools/make-assets.py` (нужен Pillow), скриншоты для Play: `python3 tools/screenshots.py ru|en` (нужен Playwright).
