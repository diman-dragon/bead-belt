# Публикация в Google Play: на потом

> **Сейчас идёт разработка, ничего не публикуем.** Файл нужен, когда дойдёт до релиза. Общий ключ из `signing/` для Play **не годится**: нужен отдельный закрытый ключ загрузки. Релизный workflow (AAB, секреты, автозагрузка) в CI сейчас удалён; его придётся вернуть при подготовке релиза.

Требования Google на октябрь 2026. Пункты, помеченные 🔎, сверьте в Play Console: формулировки и формы там меняются.

## 1. Технические требования (проект уже настроен)

| Требование | Статус |
|---|---|
| Новые приложения и обновления должны таргетить **Android 16 (API 36)** или выше (действует с 31.08.2026) | `scripts/patch-android.mjs` поднимает `compileSdk`/`targetSdk` до 36; CI падает, если меньше (`npm run check:android`) |
| Загрузка в формате **AAB** (не APK) | CI собирает `bundleRelease` |
| Подпись + **Play App Signing** | свой ключ загрузки (upload key), Google переподписывает финальный |
| Растущий `versionCode` | считается из версии: `X*100 + Y*10 + Z` (0.1.0 → 10) |
| Уникальный `appId`, не `com.example.*` | сейчас `dev.beadbelt.game`; перед релизом замените на свой, после публикации менять нельзя |
| Нативного кода нет (только WebView) | требования 64-бит и 16 КБ страниц памяти к вам не применяются, пока вы не добавите нативные библиотеки |

На API 36 приложение рисуется под системными панелями (edge-to-edge) и не получает старых событий кнопки «Назад». В игре отступы берутся из `env(safe-area-inset-*)`, кнопку «Назад» обрабатывает `@capacitor/app`. **Обязательно проверьте на эмуляторе Android 16 или реальном телефоне**: шапка не должна залезать под статус-бар, жест «Назад» должен открывать паузу.

## 2. Аккаунт разработчика

1. Регистрация в Play Console: разовый взнос 25 $, подтверждение личности.
2. **Личный аккаунт, созданный после 13.11.2023:** перед выходом в продакшен нужно провести **закрытое тестирование минимум с 12 тестерами, которые остаются подписанными 14 дней подряд**, затем подать заявку «Apply for production» (проверка обычно до 7 дней). Это самый долгий этап: начните с него как можно раньше.
3. Аккаунт организации требует D-U-N-S. 🔎 Также проверьте актуальные правила верификации разработчиков для вашей страны.

## 3. Ключ подписи (один раз)

```bash
keytool -genkeypair -v -storetype PKCS12 -keystore upload.keystore \
  -alias upload -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 upload.keystore > keystore.b64      # macOS: base64 -i upload.keystore -o keystore.b64
```

Секреты репозитория (GitHub → Settings → Secrets and variables → Actions):

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | содержимое `keystore.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | пароль ключа |
| `PLAY_SERVICE_ACCOUNT_JSON` | *(необязательно)* JSON сервисного аккаунта для автозагрузки |

Переменные репозитория: `PLAY_PACKAGE_NAME` (ваш appId, если нужна автозагрузка), `VERSION_CODE_OFFSET` (необязательно).

Хранилище `.keystore` и пароли **не коммитьте** и сохраните в надёжном месте: без upload key обновления придётся восстанавливать через поддержку.

## 4. Релиз

1. Замените `appId` в `capacitor.config.json` на свой.
2. `git tag v1.0.0 && git push --tags`: workflow соберёт подписанный AAB и положит в артефакты (Actions → запуск → Artifacts).
3. **Первый AAB загрузите в Play Console вручную** (Testing → Closed testing → Create release). Автозагрузка через API работает только после создания приложения и первого ручного релиза.
4. Пригласите 12+ тестеров (список e-mail или Google-группа), дождитесь 14 дней, подайте заявку на продакшен.

## 5. Раздел «Policy / App content» в Play Console 🔎

- **Политика конфиденциальности**: публичная ссылка. Шаблон: `PRIVACY.md` (в этой же папке); выложите, например, на GitHub Pages.
- **Data safety**: игра не собирает и не передаёт данные, всё хранится локально (`localStorage`). Отметьте «данные не собираются». Если добавите рекламу или аналитику, форму придётся переделать.
- **Ads**: «нет рекламы» (пока не добавили).
- **Content rating**: анкета IARC, в игре нет насилия, азартных механик и покупок.
- **Target audience**: выберите возрастную группу осознанно. Если включить аудиторию до 13 лет, действует политика Families (ограничения на рекламу и SDK).
- **App access**: без входа в аккаунт, доступ ко всему без ограничений.
- Декларации (новости, здоровье, финансы, госприложение): «нет».
