# Таблицы уровней

`python3 tools/gen_levels.py` печатает `ATTEMPT` и `BELTS` для `Levels.kt`. Скрипт содержит точные копии `Rng`, `Levels.layout`
и `Planner` на Python: для каждого уровня он перебирает попытки раскладки, берёт первую, у которой минимальная лента модели
не ниже целевой кривой сложности, и добавляет запас на непредсказуемость воронки (10 на уровнях 1–100, 9 на 101–300, 8 дальше).
Менял `Levels.layout`, `Planner.kt` или правила — поправь и скрипт, затем перегенерируй таблицы. Совпадение Kotlin и Python
проверяет `LevelsTest.layoutsMatchTheGenerator`.

Запас взят из калибровки по старым уровням (там лента была подобрана по настоящей физике): она в среднем на 5–6 больше
минимума модели, а у 90% уровней — не больше чем на 10–11. Реальную физику скрипт не гоняет, поэтому после изменений
стоит запустить `PlannerTest.followingHintsWinsAlmostAlways`; если какой-то уровень не проходится, подними его ленту
методом ниже.

# Пересчёт вместимости ленты

Вместимость ленты каждого уровня лежит в таблице `BELTS` (`Levels.kt`) и подобрана заранее, поэтому на устройстве
уровень создаётся мгновенно, без поиска.

Игра непредсказуема по замыслу (воронка перемешивает шарики), поэтому лента подбирается статистикой: берётся игрок,
который после каждого хода слушается `Hints.advise`, и для каждого уровня ищется наименьшая лента, при которой он
выигрывает не реже 28 раз из 30 на разных seed физики (`Game(level, seed)`), стартуя с `Planner.minCap`. Если ни при какой
ленте до 30 этого не достичь, меняется попытка раскладки (`ATTEMPT`).

## Когда пересчитывать
Если менял `Levels.layout`, правила коробок или ленты в `Game.kt`, физику воронки или `Planner.kt`, прогони
`PlannerTest.followingHintsWinsAlmostAlways` и `LevelsTest`. Упали — пересчитай таблицу: для каждого уровня запусти
партию бота-с-подсказкой (`Game(level, seed)`, ход по `Hints.advise` каждый раз, когда `Hints.calm`) на 30 seed и поднимай
ленту, пока побед не станет ≥ 28.
